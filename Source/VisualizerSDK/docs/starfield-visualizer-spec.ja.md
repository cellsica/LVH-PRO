# StarfieldVisualizer プラグイン仕様書

**対象プラグイン:** StarfieldVisualizer  
**バージョン:** 1.0  
**対象読者:** サードパーティ開発者（バイブコーダー含む）

---

## 1. 概要

StarfieldVisualizer は、音楽に反応する「宇宙空間を飛行する」感覚のビジュアライザープラグインです。

2つの視覚レイヤーが連動します。**アンビエントドット**は常に奥から手前へ流れる星のように漂い、音量が上がるにつれてその密度が増します。**バンドタイル**は16の周波数バンドに対応した輝く板が円周上に配置され、カメラに向かって飛んでくるように迫ってきます。静かなパッセージでは青みがかったタイルがゆっくりと浮かび、激しい音楽では赤く燃えるようなタイルが高密度で押し寄せます。

**推奨キャンバスサイズ:** 520 × 520 px

---

## 2. 描画レイヤー構成

描画は以下の2つのレイヤーを順番に重ねて行います。

| レイヤー順 | レイヤー名 | 内容 |
|:---:|:---|:---|
| 1 | アンビエントドット（Ambient Dots） | 奥から手前へ流れる点群。常時表示 |
| 2 | バンドタイル（Band Tiles） | 周波数バンドに対応した飛来するタイル群 |

バンドタイルはアンビエントドットの上に描画されます。

---

## 3. FFT データ処理

### 3.1 入力

- FFT サイズ: **512 ビン**（`kRawBins = 512`）
- 使用周波数レンジ: bin 1 〜 bin 480（DC 成分・ナイキスト近傍を除外）

### 3.2 16バンドへの集約

512 ビンを **16 のログスケールバンド**に集約します。

```
bandBounds: log2(1) 〜 log2(480) を 16 等分
```

各バンドに対応するビン範囲の振幅平均を計算し、`band[0..15]` として格納します。

```
band[b] = average( fftMagnitude[binStart..binEnd] )
```

ログスケールにより、低周波数域（bass）は細かく、高周波数域（treble）は広く集約されます。

### 3.3 全体エネルギーの計算

アンビエントドットのスポーンレート計算に使用する全体エネルギー正規化値：

```
avgAllBands  = average( band[0..15] )
overallNorm  = min( 1.0, sqrt(avgAllBands / 0.0005) )
```

各バンドの個別エネルギー正規化値（タイルスポーンレート計算に使用）：

```
energyNorm[b] = min( 1.0, sqrt(band[b] / 0.002) )
```

## 4. アンビエントドット仕様

### 4.1 概要

アンビエントドットは、音楽の静寂・活発を問わず常時表示される1ピクセルの点群です。遠方（奥）から手前へ向かって移動し、星空を突き抜けるような没入感を演出します。

### 4.2 パースペクティブ投影

各ドットは 3D 空間座標 `(x, y, z)` を持ちます。

```
// スクリーン座標への変換
screenX = cx + (x / z) * scale
screenY = cy + (y / z) * scale
```

- `z` の値が小さい（手前）ほどスクリーン上の位置が中心から大きく離れます。
- ドットの表示サイズは常に **1px 固定**（パースペクティブサイズスケーリングなし）。

### 4.3 スポーン（生成）ルール

新しいドットは以下のルールで生成されます。

- **生成位置:** 中心付近のランダムな小さい `(x, y)` 座標、`z = kZFar`（1.0 = 奥）
- **移動:** 毎フレーム `z -= kDotSpeed`

`z` が `kZNear`（0.05）を下回るとドットは消滅し、新たに奥から再生成されます。

### 4.4 動的スポーンレート

スポーン間隔（フレーム数）は音量に応じて動的に変化します。

```
spawnInterval = kDotSpawnSilent - (kDotSpawnSilent - kDotSpawnLoudest) * overallNorm
```

| 状態 | フレーム間隔 | 1秒あたり生成数（60fps時） |
|:---|:---:|:---:|
| 無音（overallNorm = 0） | 14 フレーム | 約 4個/秒 |
| 最大音量（overallNorm = 1） | 4 フレーム | 約 15個/秒 |

同時最大ドット数は `kMaxDots`（180個）で制限されます。

### 4.5 関連定数

| 定数名 | 値 | 説明 | 変更効果 |
|:---|:---:|:---|:---|
| `kMaxDots` | 180 | 同時表示ドットの最大数 | 増やすと星が密になる。多すぎるとパフォーマンス低下 |
| `kDotSpeed` | 0.0026 | z 軸方向の移動速度/フレーム | 大きくすると星が速く流れる。小さくするとゆっくり |
| `kDotSpawnSilent` | 14 | 無音時のスポーン間隔（フレーム） | 大きくすると無音時の星が減る |
| `kDotSpawnLoudest` | 4 | 最大音量時のスポーン間隔（フレーム） | 小さくすると大音量時の星が増える |
| `kZNear` | 0.05 | ドット消滅のニア平面 z 値 | 大きくするとドットが早く消える |
| `kZFar` | 1.0 | ドット生成の奥行き z 値 | 小さくすると出現距離が近くなる |

## 5. バンドタイル仕様

### 5.1 概要

バンドタイルは16の周波数バンドそれぞれに対応した矩形タイルで、円周上に配置されカメラに向かって飛来します。音楽のエネルギーが高いバンドほど高頻度でタイルが生成され、色は音量に応じて青（静か）から赤（大音量）へ変化します。

### 5.2 円周上のバンド配置

各バンドのタイルは、円周上に等間隔で配置されます。

```
angle[b] = b * 2π / kBands    (b = 0..15)
```

タイルのワールド座標中心：

```
worldX = cos(angle[b]) * kOrbitRadius   // kOrbitRadius = 0.40
worldY = sin(angle[b]) * kOrbitRadius
```

### 5.3 タイルの向きと形状

タイルは接線方向（円の接線）に対して横向き（ワイド側）に向きます。

```
tangX = -sin(angle[b])    // 接線方向 X
tangY =  cos(angle[b])    // 接線方向 Y
radX  =  cos(angle[b])    // 半径方向 X
radY  =  sin(angle[b])    // 半径方向 Y
```

タイルの幅（接線方向）：

```
worldW = kOrbitRadius * 2π / kBands * 0.75   // 円弧幅の 75%
```

タイルの高さ（半径方向）：

```
worldH = kTileWorldH   // = 0.040（固定）
```

4つの頂点は接線方向 `±hw` × 半径方向 `±hh` で定義されます。

### 5.4 パースペクティブ投影

タイルは z 値に基づいてパースペクティブ投影されます。

```
screen_w = worldW / z * scale
screen_h = worldH / z * scale
screenX  = cx + (worldX / z) * scale
screenY  = cy + (worldY / z) * scale
```

z 値が小さいほど（手前に近いほど）タイルは大きく、画面の端に近くなります。

### 5.5 ライフサイクル

| フィールド | 説明 |
|:---|:---|
| `life` | 生成時 `1.0` から開始。毎フレーム `speed / (kZFar - kZNear)` ずつ減算 |
| `z` | 生成時 `kZFar`。毎フレーム `speed` ずつ減算 |
| 消滅条件 | `z < kZNear` または `life <= 0` |

`speed` は `kTileSpeedMin`〜`kTileSpeedMax` の範囲でランダムに決まります。

### 5.6 輝度とアルファ

タイルはライフサイクルに応じて生成直後は明るく、消える寸前は暗くなります。

```
bri  = 0.25 + life * 0.75    // 輝度（0.25〜1.0）
alph = 0.15 + life * 0.85    // アルファ（0.15〜1.0）
```

### 5.7 ドップラーカラー

タイルの色は、そのバンドのエネルギー正規化値（`energyNorm`）に基づきます。

```
hue = 0.65 * (1 - energyNorm)
```

| energyNorm | hue | 色 |
|:---:|:---:|:---|
| 0.0（無音） | 0.65 | 青 |
| 1.0（最大音量） | 0.0 | 赤 |

### 5.8 トレイル（残像）

各タイル本体の前方（奥）に4ステップの残像を描画します。

```
// step: 4 → 1 の順番で奥から手前に描画（本体が最も手前）
trail_z = z + step * speed * kTrailSpacing   // step=4が最奥
```

| 定数名 | 値 | 説明 |
|:---|:---:|:---|
| `kTrailSteps` | 4 | 残像ステップ数 |
| `kTrailSpacing` | 5.0 | 残像間の z 方向間隔係数 |

残像はステップが遠いほどアルファを下げて描画します。

### 5.9 先端ハイライト

タイルの外縁（半径方向の遠端）に明るいハイライトストリップを描画します。これによりタイルに立体感と速度感が生まれます。

### 5.10 スポーンレート

各バンドのタイルスポーン間隔：

```
spawnInterval[b] = max( kTileSpawnLoud, kTileSpawnQuiet * (1 - energyNorm[b]) )
```

| 状態 | フレーム間隔 |
|:---|:---:|
| 無音（energyNorm = 0） | `kTileSpawnQuiet` = 22フレーム |
| 最大音量（energyNorm = 1） | `kTileSpawnLoud` = 8フレーム |

同時最大タイル数は `kMaxTiles`（`kBands * 22` = 352個）で制限されます。

## 6. チューニングガイド

以下の定数を変更することでビジュアルの性質を大きく変えられます。

| 定数名 | 値 | 説明 | 変更効果 |
|:---|:---:|:---|:---|
| `kRawBins` | 512 | FFT ビン数 | 変更時はバンド集約ロジックの見直しが必要 |
| `kBands` | 16 | 周波数バンド数 | 増やすとタイルが増え細かくなる。配置計算も要調整 |
| `kMaxDots` | 180 | アンビエントドット最大数 | 増やすと星が密になる |
| `kDotSpeed` | 0.0026 | ドット移動速度/フレーム | 大きくすると星が速く流れる |
| `kDotSpawnSilent` | 14 | 無音時ドットスポーン間隔 | 大きくすると無音時の星が疎になる |
| `kDotSpawnLoudest` | 4 | 最大音量時ドットスポーン間隔 | 小さくすると大音量時の星が密になる |
| `kMaxTiles` | kBands×22 | タイル最大数 | 増やすとより多くのタイルが同時表示可能 |
| `kOrbitRadius` | 0.40 | タイル配置の円軌道半径（正規化） | 大きくすると円が広がる。小さくすると中心に密集 |
| `kTileWorldH` | 0.040 | タイルの高さ（半径方向、ワールド座標） | 大きくするとタイルが縦長になる |
| `kTileSpeedMin` | 0.018 | タイルの最低移動速度 | 大きくすると最遅タイルでも速くなる |
| `kTileSpeedMax` | 0.095 | タイルの最高移動速度 | 大きくすると最速タイルがより速くなる |
| `kTileSpawnLoud` | 8 | 最大音量時タイルスポーン間隔 | 小さくすると大音量時に大量タイルが飛来 |
| `kTileSpawnQuiet` | 22 | 無音時タイルスポーン間隔 | 大きくすると無音時のタイルが疎になる |
| `kZNear` | 0.05 | ニア平面（消滅 z 値） | 大きくするとタイルが画面の手前で消える |
| `kZFar` | 1.0 | ファー平面（生成 z 値） | 小さくすると生成距離が近くなる |
| `kTrailSteps` | 4 | トレイルのステップ数 | 増やすと長い残像になる |
| `kTrailSpacing` | 5.0 | トレイル間隔係数 | 大きくすると残像が広がる |

## 7. バイブコーディング向けプロンプト例

以下のプロンプトを AI アシスタントに貼り付けることで、プラグインの改造アイデアを素早く得られます。

---

**プロンプト例 1: タイルのカラーをグリーン系に変更**

```
LVH の StarfieldVisualizer プラグインを改造したい。
現在、バンドタイルの色は energyNorm=0（無音）のとき hue=0.65（青）、
energyNorm=1（最大音量）のとき hue=0.0（赤）になっている。
これをエネルギーが低いときはライムグリーン（hue=0.25）、
高いときはターコイズ（hue=0.50）に変化するように書き換えてほしい。
変更箇所は StarfieldVisualizer.cpp のドップラーカラー計算部分のみでよい。
```

---

**プロンプト例 2: 星の流れを速くしてスピード感を強調する**

```
LVH の StarfieldVisualizer プラグインで、
現在 kDotSpeed=0.0026、kTileSpeedMin=0.018、kTileSpeedMax=0.095 になっている。
全体的に宇宙を高速で飛び抜けるようなスピード感を出したい。
これらの定数を調整する具体的な値の提案と、
その場合にトレイル（kTrailSpacing）も合わせて調整すべきかどうかを教えてほしい。
```
