# 【しずく（Claude Code）への依頼】to_shizuku_009：UIコンポーネントの分離とMain.cppのモジュラー化

## 1. 依頼内容
LVH の Ver 1.0 正式リリース、および将来の Pro 版（マルチプロセス/独立ウィンドウ構成）への移行をスムーズにするため、現在 `Main.cpp` に巨大な塊として存在している UI コンポーネント群を独立したファイルに切り出してください。

## 2. 実装のゴール

### A. コンポーネントのファイル抽出
以下のクラスを、それぞれ独立したヘッダー（.h）と実装ファイル（.cpp）に分離してください。
1.  **LevelMeter**: ツールバーのレベルメーター
2.  **InfoMonitorPanel**: MIDIログやDSP負荷を表示するモニターパネル
3.  **SettingsWindow (および関連ページクラス)**: 設定ウィンドウ全体
4.  **UI Utility群**: `IconButton`, `LvhLogoLabel`, `SpeakerButton` 等

### B. Header-Onlyロジックの整理
- `Main.cpp` の冒頭にある `Icons` などのユーティリティ名前空間や定数定義を `UiCommon.h` 等にまとめてください。

### C. MainComponent の軽量化
- `MainComponent` クラス定義は `MainComponent.h` に、実装は `MainComponent.cpp` に分離してください。
- `Main.cpp` には `JUCEApplication` の本体と `MainWindow` クラスのみが残る、スリムな状態にしてください。

## 3. 重要：設計上の注意点（Pro版への布石）
- **依存関係の最小化**: 各コンポーネントが `MainComponent` 全体を参照しなくても動くよう、必要な時だけコールバック（`std::function`）やポインタを渡す形を維持・徹底してください。
- **名前空間**: 必要に応じて `Lvh::Ui` 等の名前空間を使い、コードの整理を行ってください。
- **ビルドの維持**: もちろん、分離後もこれまで通りビルドが通り、機能が変わらないことを確認してください。
