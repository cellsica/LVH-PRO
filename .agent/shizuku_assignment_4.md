# 【しずく（Claude Code）への依頼】第4回：ホスト主導のプリセット管理システムの実装

## 1. 依頼内容
プラグインの状態（音色設定）をホスト側で一括管理し、現場で迷わず切り替えられる「プリセット管理機能」の実装をお願いします。
なべさんの「ユーザーにファイルパスを意識させない」という構想と、茜さんの「上書き保存が欲しい」という現場の声を形にしてください。

## 2. 仕様・設計方針

### A. プリセットの保存場所と規約
- **ルートパス**: `%AppData%/cellsica/LIGHT-VST-HOST/Presets/`
- **フォルダ構成**: `Presets/[プラグインの表示名]/`
  - プラグインごとにフォルダを分け、そのプラグイン専用のプリセットファイルのみを格納します。
- **ファイル形式**: XML
  - タグ `PresetName`: ユーザーが入力した表示名
  - タグ `PluginDescription`: 互換性チェック用のプラグイン情報
  - タグ `StateData`: Base64 エンコードされたプラグインのパラメータ（MemoryBlock）

### B. PluginSlot の拡張
- `currentPresetName` (String) を保持し、現在どのプリセットがロードされているか追跡できるようにしてください。
- `savePreset(const String& name)`: 現在のプラグイン状態を XML に書き出し、規定のフォルダに保存します。
- `loadPreset(const File& file)`: XML からデータを読み込み、プラグインに流し込みます。

### C. UIの実装 (MainComponent)
- **PRESETボタン**: ツールバーのプラグイン名の隣に配置してください。
- **ポップアップメニュー**: ボタン押下時に以下の項目を表示します。
    1. **Save New Preset...**: 名前入力ダイアログ（juce::AlertWindowなど）を出し、新規保存します。
    2. **Overwrite [現在名]**: プリセットがロード済みの場合のみ表示し、現在のファイルに上書きします。
    3. **--- 分切り線 ---**
    4. **保存済みリスト**: そのプラグインのフォルダ内にある XML ファイルを一覧表示し、クリックで即ロードします。
- **フィードバック**:
    - ロード中のプリセットにはメニュー上でチェックマークをつけるなど、現在の状態を一目で分かるようにしてください（茜さん提言）。

## 3. 実装のポイント
- プラグインが未ロードの状態では PRESET ボタンを無効化（または非表示）にしてください。
- プリセット名にファイルシステムで禁止されている文字（\ / :* ? " < > |）が含まれている場合のサニタイズを忘れないでください。
- `juce::MemoryBlock` を文字列として XML に書き出す際は、`toBase64Encoding()` / `fromBase64Encoding()` が便利です。
